# Spider Panel — Telegram Admin Bot

ربات تلگرام خصوصی (فقط برای ادمین) که به API پنل [spider--panel](https://github.com/xxkhosma15/spider--panel) وصل میشه و این کارها رو از تلگرام انجام میده:

- لیست کاربران پنل
- ساخت کاربر جدید (انتخاب اینباند، سقف ترافیک، مدت اعتبار)
- گرفتن کانفیگ (متن) و QR هر کاربر
- حذف کاربر

## نصب و اجرا (لوکال یا هر سرور)

```bash
pip install -r requirements.txt
cp .env.example .env
# مقادیر داخل .env رو پر کن (پایین توضیح داده شده)
python bot.py
```

## متغیرهای محیطی (.env)

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات که از [@BotFather](https://t.me/BotFather) می‌گیری |
| `ADMIN_CHAT_ID` | آیدی عددی تلگرام خودت (از [@userinfobot](https://t.me/userinfobot) بگیر) — ربات فقط به این آیدی جواب میده |
| `PANEL_URL` | آدرس پنل روی Railway، مثلاً `https://your-panel.up.railway.app` (بدون `/` آخر) |
| `PANEL_ADMIN_PASSWORD` | همون پسوردی که با اون وارد داشبورد وب پنل میشی |

## دیپلوی روی Railway (اختیاری)

اگه می‌خوای ربات هم مثل پنل روی Railway بالا باشه:

1. این پوشه رو توی یه ریپوی جدید گیت‌هاب push کن.
2. توی Railway: **New Project → Deploy from GitHub → این ریپو رو انتخاب کن**.
3. متغیرهای بالا رو توی تب Variables ست کن.
4. چون این یه ربات polling-محوره (نه وب‌سرور)، نیازی به دامین یا پورت نیست — همینکه `python bot.py` اجرا بشه کافیه (Railway به‌صورت پیش‌فرض `python bot.py` رو با نبود healthcheck هم به عنوان یک worker process اجرا می‌کنه).

## نکته مهم درباره‌ی فیلدهای API

مستندات API پنل (بخش README خود ریپو) اسم دقیق همه‌ی فیلدهای بدنه‌ی درخواست `POST /api/users` رو نداده. توی `bot.py` تابع `create_user_confirmed` این فیلدها رو می‌فرسته:

```python
{
    "username": ...,
    "inbound_ids": [...],
    "traffic_limit_gb": ...,
    "expire_days": ...,
}
```

اگه بعد از تست دیدی پنل خطای فیلد نامعتبر میده، کافیه همین یه‌جا (تابع `create_user_confirmed` توی `bot.py`) رو با اسم فیلدهای واقعی که توی `main.py` خود پنل تعریف شده هماهنگ کنی — بقیه‌ی کد (لیست، حذف، کانفیگ، QR) دست‌نخورده کار می‌کنه چون این‌ها فقط `id` کاربر رو لازم دارن.

## گسترش دادن ربات

`panel_client.py` تقریباً همه‌ی endpointهای مستند‌شده‌ی پنل رو پوشش می‌ده (کاربران، اینباندها، آمار سرور). اگه بعداً خواستی بخش‌های دیگه (مدیریت Worker کلادفلر، اسکنر آی‌پی، گروه‌ها، آمار زنده‌ی سرور) رو هم به ربات اضافه کنی، همون الگوی موجود توی `bot.py` (یه تابع async برای هر endpoint + یه دکمه‌ی اینلاین که callback_data مربوطه رو صدا بزنه) رو تکرار کن.

## امنیت

- این ریپو پسورد یا توکن رو داخل کد نمی‌ذاره — همه از `.env` خونده میشه. `.env` رو هیچ‌وقت push نکن (توی `.gitignore` بذارش).
- ربات فقط به `ADMIN_CHAT_ID` جواب میده؛ هر پیام از هر آیدی دیگه نادیده گرفته میشه.
